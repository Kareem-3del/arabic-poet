# Form Without Meaning

**What a hard meter constraint guarantees, what it cannot, and the gap between acceptance and
quality in Arabic poetry generation.**

Report: [English](paper/PAPER.md) ([PDF](paper/PAPER.pdf)) · [العربية](paper/PAPER.ar.md)
([PDF](paper/PAPER.ar.pdf)) · [شرح مبسّط](paper/SUMMARY.ar.md) · [README بالعربية](README.ar.md)

## What this is

We fine-tuned two language models to write fully diacritized classical Arabic verse and decoded
them under a filter that rejects, token by token, anything that would break the requested
meter, rhyme letter or vocabulary. Then we asked what the filter actually buys.

- **A constraint guarantees what is written into it, and no more.** Each constraint moves its
  own measure: the meter filter takes accepted hemistichs from 0.37 to above 0.95.
- **It does not reach what readers judge.** Two blind human readers rate the constrained model
  as they rate the free one on topic, connection and language.
- **Acceptance by a checker is not quality.** The acceptor accepts 0.95 of hemistichs that the
  same readers rate 2.5 of 10 for meter; a published system's 94.8% classifier accuracy
  corresponds to 34.2% of abyat passing a scansion checker.

Three hosted general-purpose models, given only the prompt, land in the same range on the
acceptor and far above for the readers. The report states its limits plainly: the readers are
not specialists, no prosodist has audited the acceptor, and the sample is 30 prompts.

## Layout

```
paper/            the report (Markdown and PDF, English and Arabic), figures, results
  data/           every poem behind the tables, with per-poem scores; human ratings (scores only)
  REPRODUCIBILITY.md   file hashes, versions, what a rerun can reproduce
src/arabic_poet/
  poetry/         'arud acceptor (arud_fsa.py), vocabulary acceptor, scansion checker
  generation/     constrained decoder for MLX and PyTorch (constrained.py), prompts
  models/         model loading
scripts/          one script per step; see scripts/README.md
data/benchmarks/  the 30 prompts of the report and 30 held-out prompts
cloud/sagemaker/  training and in-job evaluation of Jais-3-32B
kaggle/           training notebooks for ALLaM-7B
tests/            tests of the acceptors
```

## Quick start

```bash
uv sync                      # Python 3.12 and pinned dependencies
uv run pytest -q             # acceptor tests

# Rebuild every table and figure of the report from the saved poems (no model needed)
uv run python scripts/paper_tables.py
uv run python scripts/paper_figures.py
uv run --with markdown python scripts/build_paper_pdf.py     # needs Chrome
```

Generating new poems needs a model and an adapter, which are not in this repository:

```bash
uv run python scripts/eval_constrained.py <adapter_dir> out.json 30 free,lexicon
```

Modes: `free`, `form`, `rhyme`, `vocab`, `meter`, `constrained` (meter + rhyme), `lexicon`
(all constraints).

## What is not here

- **Model weights and adapters.** Base models: `humain-ai/ALLaM-7B-Instruct-preview` and
  `inception42/Jais-3-32B`. The fine-tuned adapters are not published yet.
- **The training corpus.** Poems transcribed on Arabic Wikisource (CC BY-SA) by authors who
  died in or before 1975. `scripts/build_tashkeel_sft.py` rebuilds the training set from a
  corpus dump; hashes of the exact files used are in `paper/REPRODUCIBILITY.md`.
- **The raters' written notes.** Scores are published; notes are not.
